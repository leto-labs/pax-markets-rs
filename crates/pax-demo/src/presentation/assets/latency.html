How to read this measurement

The selected first-read window or completion batch is a proxy for packet ingress. Where both associated read ends are available, the timeline separates time between reads from time after the last read. The former includes input availability, transport work and scheduling; the latter includes remaining TLS/framing and buffered residence. Exact first contributing packet and last required TLS-record arrival are unavailable. Read-ahead and buffered messages limit attribution. Clock uncertainty does not bound this packet-position ambiguity. Active socket/TLS operation windows below are separate diagnostics and are not added to this timeline.

Socket, TLS & WebSocket

Timing boundaries & coverage

Active poll wall time includes possible preemption. TLS adapter work includes authentication, buffering and copying; it does not isolate cryptographic instructions. The read window can omit earlier buffered TLS bytes or include read-ahead. First contributing packet and last required authenticated TLS record remain unavailable. Shared batch work is counted once by the operation that performed it; it is not duplicated onto buffered messages. Pending time is separate and includes idle input waits and scheduling.
